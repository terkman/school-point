# Acceptance tests

รายการ P0 ด้านล่างต้องผ่านทั้งหมดก่อนนำข้อมูลนักเรียนจริงเข้า

## Authentication และความเป็นส่วนตัว

- รหัสเปิดใช้งานครั้งแรกเป็นค่าสุ่ม ใช้ครั้งเดียว และหมดอายุได้
- วันเกิดใช้เป็นรหัสผ่านถาวรไม่ได้
- ข้อความล็อกอินผิดไม่เปิดเผยว่ามี username นั้นอยู่หรือไม่
- นักเรียนเปลี่ยน URL/ID แล้วอ่านข้อมูลนักเรียนคนอื่นไม่ได้
- response สำหรับนักเรียนไม่มีชื่อ รหัส อีเมล หรือ UUID ของผู้บันทึก
- anon user อ่านตารางข้อมูลส่วนบุคคลไม่ได้
- ไม่มี `.env`, service-role key, ข้อมูลจริง หรือรหัสเปิดใช้งานใน Git history/production bundle

## ครูและขอบเขตห้องเรียน

- ครูเห็นเฉพาะห้องที่ได้รับมอบหมาย
- เรียกข้อมูลหรือตัดคะแนนนักเรียนต่างห้องโดยตรงแล้วฐานข้อมูลปฏิเสธ
- ตัด 5 คะแนนจาก 100 แล้วได้ 95 ทันที พร้อม ledger/audit
- คะแนน 3 แล้วตัด 5 เหลือ 0 ไม่เป็นค่าติดลบ และเก็บ requested/applied delta ถูกต้อง
- ครูขอคืนคะแนนแล้วคำขอเป็น pending และคะแนนยังไม่เปลี่ยน
- ครูเรียก RPC เพิ่มคะแนนโดยตรงแล้วถูกปฏิเสธ

## แอดมินและธุรกรรมคะแนน

- อนุมัติคำขอครั้งเดียวแล้วเพิ่มคะแนนและมี ledger/audit
- กดอนุมัติคำขอเดิมซ้ำแล้วคะแนนไม่เพิ่มซ้ำ
- ปฏิเสธคำขอแล้วคะแนนไม่เปลี่ยนและเก็บเหตุผล
- คะแนน 98 แล้วขอเพิ่ม 5 ได้ผลตามนโยบาย cap ที่ 100 และเก็บ applied delta 2
- ผู้ใช้แอปแก้หรือลบ ledger/audit เดิมไม่ได้
- ครูสองคนตัดนักเรียนคนเดียวพร้อมกันแล้วไม่มี lost update
- ยอดคงเหลือสอดคล้องกับ ledger ทุกคน

## อุทธรณ์ ภาคเรียน และกรณีร้ายแรง

- ยื่นอุทธรณ์ที่เวลาเท่ากับ 7 วันพอดีได้ และช้ากว่าหนึ่งมิลลิวินาทีไม่ได้
- ส่งอุทธรณ์ซ้ำ incident เดิมไม่ได้
- อนุมัติอุทธรณ์สร้าง compensating transaction ไม่แก้รายการเดิม
- เปิดภาคเรียนใหม่แล้วเริ่ม 100 และสั่งซ้ำไม่สร้าง opening entry ซ้ำ
- เคสติดตามที่ยังไม่เสร็จยังอยู่หลังเปลี่ยนภาคเรียน
- เหตุทั่วไปไม่สร้างงานติดต่อผู้ปกครอง
- เหตุร้ายแรงสร้าง follow-up case และ guardian-contact task
- ยืนยันจบ ม.3 แล้วเปลี่ยนสถานะเป็น archived/graduated แต่ไม่ลบประวัติ

## UI และ browser QA

- ทดสอบที่ 1440×900, 768px และ 390×844 โดยข้อความไทยไม่ล้นหรือทับกัน
- ใช้คีย์บอร์ดได้ครบ มี focus ที่มองเห็นได้ และฟอร์มมี label
- loading/empty/error state ไม่แสดงหน้าขาว
- ไม่มี Vite overlay หรือ console error จากแอป
- ทดสอบ flow ครบ: ครูตัดคะแนน → ครูขอเพิ่ม → แอดมินอนุมัติ → นักเรียนเห็นคะแนน → นักเรียนอุทธรณ์

## ชุดทดสอบอัตโนมัติที่ควรเพิ่มเมื่อเชื่อม Supabase

- Unit: clamp คะแนน, เส้นตาย 7 วัน, validation และ demo reducer
- Database: RLS matrix, RPC ตัดคะแนน, approval แบบ idempotent, concurrent deduction, term initialization
- E2E: login ทั้ง 3 บทบาทและ flow สำคัญข้างต้น
- CI gate: typecheck, test, production build และ database tests
