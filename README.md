# School Point

ระบบบริหารคะแนนความประพฤตินักเรียนสำหรับนักเรียน คุณครู และผู้ดูแลระบบ รองรับทั้งโหมดสาธิตและ Supabase คะแนนเริ่มต้นภาคเรียนละ 100 คะแนน และทุกการเปลี่ยนแปลงมีประวัติตรวจสอบย้อนหลัง

> Repository นี้เป็นสาธารณะ ห้ามใส่ข้อมูลนักเรียนจริง secret, OTP, `.env.local` หรือหลักฐานเหตุการณ์ลง Git ข้อมูลจริงต้องอยู่ใน Supabase และไฟล์ local ที่ถูก ignore เท่านั้น

## สิ่งที่ใช้งานได้แล้ว

### นักเรียน

- ดูคะแนนและประวัติของตนเองเท่านั้น
- ยื่นอุทธรณ์รายการตัดคะแนนภายใน 7 วัน
- ไม่เห็นชื่อ รหัส หรือข้อมูลของผู้บันทึกรายการ
- ดูสถานะคำอุทธรณ์ของตนเอง

### คุณครู

- เห็นเฉพาะนักเรียนในห้องที่ได้รับมอบหมาย
- ตัดคะแนนได้ทันทีตามระเบียบ โดยคะแนนไม่ต่ำกว่า 0
- ขอเพิ่มคะแนนได้ แต่คะแนนจะยังไม่เปลี่ยนจนกว่าแอดมินอนุมัติ
- เหตุร้ายแรงเปิดเคสติดตามและงานติดต่อผู้ปกครองอัตโนมัติ

### ผู้ดูแลระบบ

- อนุมัติหรือปฏิเสธคำขอเพิ่มคะแนนจากคุณครู
- เพิ่มคะแนนโดยตรงพร้อมเหตุผล โดยคะแนนไม่เกิน 100
- ดูคำอุทธรณ์และคิวกรณีร้ายแรง
- รีเซ็ตคะแนนเป็น 100 เมื่อเริ่มภาคเรียน โดยคงเคสติดตามที่ยังไม่เสร็จไว้
- คืนค่าข้อมูลสาธิตเพื่อเริ่มทดลองใหม่

## กติกาธุรกิจ

- คะแนนอยู่ระหว่าง 0–100 เท่านั้น
- ครูตัดคะแนนแล้วมีผลทันที
- ครูเพิ่มคะแนนได้ผ่านคำขอที่แอดมินอนุมัติเท่านั้น
- การอนุมัติคำขอเดิมซ้ำต้องไม่เพิ่มคะแนนซ้ำ
- นักเรียนยื่นอุทธรณ์ได้ถึงเวลาบันทึกรายการ + 7 วัน
- นักเรียนไม่ได้รับข้อมูลตัวตนของผู้บันทึกจาก API/view สำหรับนักเรียน
- เปิดภาคเรียนใหม่ด้วย 100 คะแนน; มาตรการติดตามที่ยังไม่เสร็จยกไปต่อโดยไม่ยกคะแนนติดลบ
- เหตุทั่วไปไม่สร้างงานแจ้งผู้ปกครองอัตโนมัติ เหตุร้ายแรงจึงเข้าสู่ขั้นตอนดังกล่าว
- เก็บประวัติจนแอดมินยืนยันการจบ ม.3 แล้วเปลี่ยนเป็นสถานะเก็บถาวร ไม่ลบอัตโนมัติ
- ledger และ audit log เป็น append-only; การแก้ไขใช้รายการชดเชย ไม่แก้หรือลบรายการเดิม

## เริ่มใช้งานโหมดสาธิต

ต้องใช้ Node.js 22.12 ขึ้นไป

```powershell
git clone https://github.com/terkman/school-point.git
Set-Location school-point
npm install
Copy-Item .env.example .env.local
npm run dev
```

บัญชีตัวอย่าง (รหัสผ่านทุกบัญชีคือ `demo1234`):

| บทบาท | ชื่อผู้ใช้ |
|---|---|
| นักเรียน | `69001` |
| คุณครู | `teacher.demo` |
| ผู้ดูแลระบบ | `admin.demo` |

ข้อมูลสาธิตเก็บใน versioned localStorage เฉพาะเบราว์เซอร์นี้ และ session เก็บใน sessionStorage ห้ามใช้ demo mode บน production

## ใช้งานกับ Supabase

1. สร้าง Supabase project สำหรับโรงเรียนโดยเฉพาะ
2. คัดลอก `.env.example` เป็น `.env.local`
3. ตั้ง `VITE_DATA_MODE=supabase`
4. ใส่ project URL และ publishable/anon key เท่านั้น ห้ามใส่ service-role key ในตัวแปร `VITE_*`
5. ตั้ง `VITE_SUPABASE_AUTH_EMAIL_DOMAIN` ให้ตรงกับสคริปต์ provision บัญชี (ค่าเริ่มต้น `accounts.school-point.invalid`)
6. รัน migration ใน `supabase/migrations` และรัน assertions ใน `supabase/tests`
7. ปิด **Allow new users to sign up** ใน Hosted Auth และตรวจว่า Auth users เดิมเป็นบัญชีที่โรงเรียนยืนยันแล้ว
8. ตรวจ import plan แล้วนำเข้าด้วย `npm run supabase:import` จาก trusted local process; provisioning จะตรวจสถานะ public signup ซ้ำและหยุดแบบ fail-closed
9. บัญชีใหม่ถูกสร้างโดยยังไม่มีรหัสผ่านส่วนตัวที่ผู้ใช้กำหนด; ออกรหัสเปิดใช้ครั้งเดียวด้วย `npm run supabase:activation`
10. เติมวันเปิด–ปิดและเปลี่ยนภาคเรียนจาก `planned` เป็น `active` ก่อนเริ่มตัดคะแนนจริง
11. ทดสอบ RLS ด้วยบัญชีนักเรียน ครูต่างห้อง และแอดมินก่อนเปิดใช้งานจริง

```powershell
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
```

หน้าเว็บรับ username แต่ Supabase Auth ใช้อีเมลภายในแบบ deterministic: `trim().toLowerCase()` แล้วต่อกับ `VITE_SUPABASE_AUTH_EMAIL_DOMAIN` โดย username อนุญาตเฉพาะ `a-z`, `0-9`, `.`, `_`, `-` เท่านั้น สคริปต์ provision ต้องใช้สูตรและ domain เดียวกัน อีเมลนี้ไม่ใช่อีเมลจริงของนักเรียน และ client ใช้เพียง anon key ส่วนการสร้างผู้ใช้ยังต้องทำผ่าน trusted server/Edge Function เท่านั้น

บัญชีใหม่เริ่มเปิดใช้ด้วยรหัสใช้ครั้งเดียวที่ตรวจและหมดอายุฝั่งเซิร์ฟเวอร์ (รหัสเปิดใช้ 24 ชั่วโมง รหัสกู้บัญชี 1 ชั่วโมง) ซึ่งไม่ใช่รหัสผ่านชั่วคราว ผู้ใช้ต้องตั้งรหัสผ่านส่วนตัว แล้วเข้าสู่ระบบใหม่ด้วยรหัสนั้นเพื่อรับ JWT ที่ Supabase ลงลายเซ็นและมี `amr.method = password` ก่อนเรียก RPC เพื่อปลด `activation_required` ข้อมูลโรงเรียนและ RPC คะแนนทุก session ต้องผ่านทั้ง activation gate และ password AMR จึงไม่ใช้วันเกิดหรือค่า password hash ภายในเป็นหลักฐาน ดูขั้นตอนเต็มใน `docs/IMPORT_DATA.md`

## การนำเข้าข้อมูลภายหลัง

- ใช้รหัสนักเรียนเป็นตัวระบุหลัก ห้ามจับคู่ด้วยชื่อ
- ทำ dry run และ preview ก่อนนำเข้าจริง
- ตรวจรหัสซ้ำ ห้องเรียน วันที่ และแถวที่ข้อมูลไม่ครบ
- เก็บวันเกิด/ข้อมูลอ่อนไหวใน schema ส่วนตัวที่ frontend อ่านไม่ได้
- ห้าม commit Excel, CSV, `.env`, รหัสเปิดใช้งาน, หลักฐานเหตุการณ์ หรือ export ฐานข้อมูลจริง
